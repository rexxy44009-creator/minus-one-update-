# Godzilla Minus One - boss mob (NeoForge 1.21.1 + GeckoLib 4)

Entity ID `godzilla_mod:godzilla_minus_one` (`/summon godzilla_mod:godzilla_minus_one`, or the spawn egg in the creative tab).

> **Status: written carefully but NOT compiled or run** (no Minecraft toolchain was available where this was generated).
> Expect a handful of small import / signature fixes on the first build. Section 6 lists the spots most likely to need them.

## 1. Setup
1. Download the official **NeoForge MDK for Minecraft 1.21.1** (Java 21) and set `mod_id=godzilla_mod`.
2. Copy `src/` from this project over the MDK's `src/` (delete the MDK's example mod class).
3. Add the GeckoLib repo + dependency from `build.gradle.snippet` to the MDK `build.gradle`, refresh Gradle, run `runClient`.
4. A **voxel-sculpt model, animations and scale texture are already included** (generated by `tools/gen_assets.py`), so it works immediately. Replace them with a Blockbench model built from your reference images (section 4).

## 2. What is where
| File | Job |
|---|---|
| `GodzillaTuning.java` | every number: HP, damage, stage durations, beam size, crater power, radiation |
| `entity/GodzillaEntity.java` | attributes, immunities, block smashing, footsteps, boss bar, death, synced state, GeckoLib controller |
| `ai/GodzillaAtomicBreathGoal.java` | **ROAR -> CHARGE -> FIRE -> VENT** state machine (plates ignite tail->head, flashes, sounds) |
| `ai/AtomicBeam.java` | per-tick ray: carves terrain, damages/ignites, craters, radiation clouds |
| `ai/GodzillaMeleeGoal.java` | jaw bite (front) / tail swipe (rear + flanks), launch targets skyward |
| `ai/GodzillaRampageMoveGoal.java`, `GodzillaMoveControl.java` | straight-line lumbering movement (vanilla pathfinding can't handle a 7x21 mob) |
| `client/GodzillaModel.java` | head tracking + shows `plate_glow_NN` bones as plates light up |
| `client/GodzillaRenderer.java` | emissive glow layer + draws the beam from synced yaw/pitch/length |
| `client/CameraShake.java`, `GodzillaClientHooks.java` | stomp / roar / beam screen shake |
| `resources/.../sounds.json` | currently maps to **vanilla sounds as placeholders** (see 5) |

## 3. How it matches the spec
- **5,000 HP**, armor 30 + toughness 20 (vanilla caps), knockback resistance 1.0, explosion knockback resistance 1.0.
- **Immune** to normal arrows, all fire, drowning (also fall damage, Wither, and his own beam/craters). `/kill` still works.
- **Slow and lumbering**: speed 0.16, 3 deg/tick turn rate. Every 20 ticks a foot lands: custom sound, camera shake, dust, 10 damage + hop to anything standing nearby (jump to dodge).
- **Mob griefing by walking**: every 3 ticks everything inside and just ahead of his hitbox is deleted (never the ground under him; fluids and bedrock skipped; capped at 300 blocks per pass). Respects the `mobGriefing` gamerule, as do the beam and craters.
- **Aggro**: players, villagers, iron golems within 64 blocks (the FOLLOW_RANGE attribute), no line of sight needed. Creative/spectator players ignored.
- **Melee**: bite 60 dmg / tail 50 dmg, strike frames aligned to the animations (tick 14 / tick 22), victims launched ~15 blocks up.
- **Atomic breath** (only when the target is 12-64 blocks away; cooldown 20 s, 11 s below half health; cannot be interrupted once started):
  1. *Roar* 2.5 s: feet planted, turns to face target, roar + big camera shake.
  2. *Charge* 4 s: 14 dorsal plate clusters light up one at a time, tail to head (blue sparks, dust, random flash particles, rising chime; the glow overlay bones switch on, full-bright via the glowmask).
  3. *Fire* 5 s: ray shoots out, then slowly swings after the target (a moving player can outrun it). Carves a 3-block-radius tunnel (up to 600 blocks/tick), hits everything in it every 5 ticks for 35 and sets it on fire, drops TNT-sized craters on the ground under it, and leaves **Radiation** clouds (Wither II + Slowness III, 60 s) in the craters.
  4. *Vent* 2 s: steam, plates cool tail to head.

## 4. Replacing the placeholder model (keep these names and everything keeps working)
Blockbench: *Bedrock/GeckoLib model*. Model faces **-Z**. Export to `assets/godzilla_mod/geo/godzilla_minus_one.geo.json`.
- **Bones:** `root body torso head jaw mouth_glow arm_left arm_right leg_left leg_right tail_1 tail_2 tail_3`, plates `plate_00 ... plate_13` (00 = tail tip, 13 = upper back) and, for each, an enlarged copy `plate_glow_00 ... plate_glow_13` painted blue (these are the ones that light up; they are hidden when not charging).
- **Glowmask:** `textures/entity/godzilla_minus_one_glowmask.png`, same layout as the main texture, only the glowing pixels (plates, eyes, mouth) painted. GeckoLib's AutoGlowingGeoLayer renders it full-bright.
- **Animations** (file `animations/godzilla_minus_one.animation.json`, names `animation.godzilla_minus_one.<x>`): `idle walk roar charge fire vent bite tail_swipe death`. Keep the lengths in sync with `GodzillaTuning`: roar 2.5 s, charge 4 s, vent 2 s, bite 1.5 s (jaws shut at 0.7 s), tail_swipe 2.2 s (tail connects at 1.1 s), death 5 s, walk 2 s (a foot plant every 1.0 s).
- Edit `entity/PlateProfile.java` (plate positions, blocks relative to the feet) and `MOUTH_FORWARD / MOUTH_HEIGHT` in `GodzillaEntity` so particles and the beam origin match your model. Hitbox is `GodzillaTuning.HITBOX_*`.
- Reference note: the Minus One design has jagged, widely spaced dorsal plates and a charred, scarred hide. The film's charge is red-orange before the blue-white beam, so you may want a two-stage glow (swap the glow texture color) later.

## 5. Sounds
`sounds.json` uses `"type": "event"` entries that point at vanilla sounds (ender dragon growl, warden sonic charge/boom, iron golem step...) pitched down, so it is audible out of the box. To use real audio: drop `.ogg` files in `assets/godzilla_mod/sounds/` and change each entry to `{ "name": "godzilla_mod:roar" }` etc. Only use audio you have the rights to.

## 6. Where a first build is most likely to need fixes
- **GeckoLib 4.8.x signatures:** `GodzillaModel` (`getModelResource` etc. take only the animatable here; `setCustomAnimations`; `getAnimationProcessor().getBone(..).setHidden(..)`; `DataTickets.ENTITY_MODEL_DATA`), `GodzillaRenderer#getDeathMaxRotation`. The GeckoLib wiki has the current form of each.
- **Animation rotation signs** in the placeholder file are a guess (positive X = head/jaw down in Bedrock convention). If something bends the wrong way, flip the sign in the generator or Blockbench.
- **`MobEffects.MOVEMENT_SLOWDOWN`** is the 1.21.1 name (later versions call it `SLOWNESS`).
- Beam client rendering uses `RenderType.lightning()` and `VertexConsumer#addVertex(...).setColor(...)` (1.21.x vertex API).

## 7. Performance / safety notes
- Griefing is bounded per tick (300 blocks walking, 600 blocks beam, no neighbour updates for beam carving). Lower `BEAM_BLOCKS_PER_TICK` / `GRIEF_MAX_BLOCKS_PER_PASS` on weak servers.
- Beam, craters and walking all delete blocks with **no drops**. He will wreck builds: use a test world, and `/gamerule mobGriefing false` turns all of it off while keeping the damage.
- Particles use a long-range sender (192 blocks) so spectators far away still see the show; shorten in `AtomicFx` if you see packet pressure.

## 8. Porting
Current Minecraft releases are 26.x (unobfuscated, Java 25). The AI/state-machine logic ports directly, but expect renames (`hurt` became `hurtServer(ServerLevel, ...)`, effect names, GeckoLib's newer render API) so budget for rewriting `GodzillaModel`/`GodzillaRenderer`. A **Bedrock add-on** version would be a separate implementation (entity JSON + Script API for the breath state machine and block carving); say so if you want that instead.


## 9. Model notes (v3)
- The body is a voxel sculpt: smooth shapes voxelised at half-block size, surface voxels only, merged along X (about 1,900 cubes + about 400 for the spikes and their glow copies). Skin is a pixel-art reptile-scale texture with tan arc banding on chest, inner thighs and tail underside.
- Re-run `python3 tools/gen_assets.py --render` to regenerate everything and write `tools/preview_3d*.png`. Needs Python with numpy, pillow and matplotlib.
- Tilts: if spikes lean forward / the tail curls the wrong way in game, set `LEAN_SIGN = -1` at the top of `tools/gen_assets.py` and re-run.
- Mushroom cloud: `ai/AtomicBlast.java` (tuning in `GodzillaTuning`, BLAST_*). It erupts where the ray meets the ground 6 ticks before the ray ends.
